# GAN-Based Secret Image Sharing with Privacy-Aware Learning

A research prototype for learned multi-share image representation, reconstruction, and empirical privacy evaluation using convolutional neural networks and adversarial training.

The maintained system transforms an image into four learned shares and reconstructs the image from all four. Privacy-aware training uses independent single-share reconstruction attackers and a source-share association discriminator.

This is an empirical machine-learning system, not a cryptographic secret-sharing scheme. It currently provides no formal secrecy, indistinguishability, or `(k, n)` threshold guarantee.

## Research question

Can a learned four-share representation preserve high-quality reconstruction when all shares are available while reducing recoverable source information from any individual share?

The maintained evaluation therefore measures:

- Full four-share reconstruction quality.
- Fresh single-share attacker reconstruction quality for every share.
- Partial-share reconstruction as a diagnostic.
- Per-share entropy.
- Cross-share correlation.
- Privacy-discriminator accuracy.
- Training stability and reconstruction/privacy trade-offs.

## Architecture

`models/encoder.py` maps a 3-channel 256 × 256 image to four learned 3-channel shares. Each share is generated by a separate convolutional head.

`models/decoder.py` concatenates the four shares and reconstructs the source image through convolutional and transposed-convolutional layers.

`models/attacker.py` reconstructs an image from one share. Four attackers participate in Privacy-GAN training, while final evaluation trains fresh attackers from scratch against the frozen encoder.

`models/privacy_discriminator.py` learns to distinguish matched image-share pairs from mismatched pairs. The encoder is trained adversarially to make this association difficult.

The current decoder requires all four shares. It should therefore be described as a four-share learned reconstruction model, not as a formal threshold secret-sharing construction.

## Privacy-GAN objective

The maintained generator objective is:

`reconstruction loss - privacy weight × attacker reconstruction loss + GAN weight × privacy discriminator loss`

The reconstruction term preserves utility. The attacker term discourages information that enables direct single-share reconstruction. The discriminator term discourages direct source-share association.

During the generator update, attacker and discriminator parameters are frozen and their batch-normalization running statistics are not updated. Gradients can still flow through their computations to the encoder shares.

## Installation

Create a virtual environment and install the pinned dependencies:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
```

The maintained dependency pair is PyTorch 2.14.0 with TorchVision 0.29.0.

The repository uses Git LFS for `.pth` checkpoints. If checkpoints are needed, install Git LFS and initialize it before using them:

```bash
brew install git-lfs
git lfs install
git lfs pull
```

## Validate the installation

Run the architecture smoke test before a long training run:

```bash
python -m scripts.validate_project
```

It verifies the encoder share count and shapes, decoder output, attacker output, privacy-discriminator output, PyTorch version, and selected compute device.

## Training

The maintained training entry point is `training/train_privacy_gan.py`.

A controlled starting experiment is:

```bash
python -m training.train_privacy_gan \
  --train-images 10000 \
  --test-images 1000 \
  --epochs 30 \
  --batch-size 8 \
  --privacy-weight 0.10 \
  --gan-weight 0.01
```

The script is configurable from the command line and records dataset sizes, image resolution, learning rates, privacy weights, attacker steps, seed, initialization source, validation metrics, parameter counts, best epoch, and training history.

Fresh initialization is the default. An earlier privacy-sweep model can be used explicitly when desired:

```bash
python -m training.train_privacy_gan \
  --init-checkpoint-dir checkpoints/privacy_sweep/lambda_0.10
```

Best models are written to `checkpoints/privacy_gan/`.

## Evaluation

Run the maintained evaluation pipeline after training:

```bash
python -m evaluation.evaluate_privacy_gan \
  --attacker-train-images 5000 \
  --test-images 1000 \
  --attacker-epochs 10
```

The evaluator loads `encoder_best.pth` and `decoder_best.pth`, evaluates legitimate reconstruction, trains four fresh attackers, measures share statistics and discriminator performance, and saves both numerical and visual evidence.

Results:

`outputs/privacy_gan/results.json`

`outputs/privacy_gan/results.txt`

Visual evidence:

`outputs/privacy_gan/visuals/full_reconstruction_grid.png`

`outputs/privacy_gan/visuals/fresh_attacker_grid.png`

The full reconstruction grid contains the original image, all four shares, and the legitimate reconstruction. The attacker grid contains independent single-share reconstructions.

## Training plots

Training history is stored in `checkpoints/privacy_gan/training_log.csv`.

Generate plots with:

```bash
python -m evaluation.plot_privacy_gan_history
```

Plots are written to `outputs/privacy_gan/training_plots/`.

## Model comparison

For a controlled comparison of the baseline, privacy-sweep, and maintained Privacy-GAN models:

```bash
python -m evaluation.compare_privacy_models
```

The comparison uses the same fresh-attacker protocol for each available checkpoint and writes its results to `outputs/privacy_model_comparison/results.json`.

## Dataset

The current implementation uses CIFAR-10 through `torchvision`. Images are resized from 32 × 32 to 256 × 256 and converted to tensors in the range [0, 1].

The dataset is downloaded automatically into `data/`.

CIFAR-10 is a controlled prototype dataset. Results on CIFAR-10 alone do not establish generalization to high-resolution or domain-specific imagery.

## Checkpoints and experiment records

Privacy-GAN checkpoints are stored in `checkpoints/privacy_gan/`.

The maintained pipeline writes:

An earlier checkpoint recorded 32.592668 dB reconstruction PSNR at epoch 1 with privacy weight 0.10 and GAN weight 0.01. That is retained as historical provenance and is not presented as the final benchmark for the maintained pipeline.

## Scientific limitations

The project does not currently establish:

- Information-theoretic secrecy.
- Computational indistinguishability.
- Differential privacy.
- A formally proven `(k, n)` threshold property.
- Security against arbitrary inversion, inference, or membership attacks.

A low single-share attacker PSNR is evidence that the evaluated attacker reconstructed the source poorly. It is not proof that the share contains no useful information.

The partial-share experiment zero-fills missing shares. It is a diagnostic of the current decoder and must not be interpreted as a threshold-security experiment.

The next meaningful research steps are larger training runs, multiple random seeds, stronger independent attackers, perceptual metrics, explicit threat-model experiments, and comparison against all relevant baseline variants. A formal threshold requirement would require a formally defined threshold mechanism in addition to the learned representation.

## Recommended research workflow

1. Run `python -m scripts.validate_project`.
2. Train the maintained Privacy-GAN pipeline with a recorded configuration.
3. Preserve `best_info.json` and `training_log.csv` with the checkpoint.
4. Run the independent-attacker evaluation.
5. Inspect numerical results and visual grids together.
6. Generate training-history plots.
7. Repeat important experiments with multiple seeds.
8. Compare against the baseline and earlier privacy variants before making a research claim.
